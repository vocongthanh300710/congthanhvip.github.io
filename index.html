TRIP01 — Phân tích đầy đủ

Từ ý tưởng của thầy (vector V · MT) đến code C++ hoàn chỉnh — kèm chứng minh và demo.
Đồ thị có hướng Ma trận (max, +) Luỹ thừa nhanh O(N³ log T)

1. Ý tưởng cốt lõi (theo cách giải thích của thầy)

💬 Trích lời thầy:
"Ta tận dụng việc không tồn tại ràng buộc về số lần ghé thăm mỗi đỉnh để xây dựng hẳn một ma trận biến đổi cố định:
M[u, v] = điểm thưởng lớn nhất để đi từ u đến v qua đúng 1 cạnh.
Suy ra: M²[u, v] = điểm lớn nhất qua đúng 2 cạnh, …, Mk[u, v] = điểm lớn nhất qua đúng k cạnh.
Vậy để tính điểm lớn nhất để đi từ 1 đến tất cả các đỉnh sau đúng T cạnh, ta chỉ cần lấy V * MT, với V[1] = 0, V[u] = -∞ ∀u ≠ 1."

Tại sao cách nói này mạnh? Vì nó tổng quát hoá:

  • Không chỉ đỉnh 1 — mà tính được điểm đến mọi đỉnh sau T bước.
  • Vector khởi tạo V chỉ có đỉnh 1 = 0 → đúng nghĩa "xuất phát từ 1".
  • Đáp án = (V · MT)[1] — tức là quay về đỉnh 1.

1.1. Ma trận biến đổi M

Với mỗi cung u → v có thật trong đồ thị:

M[u][v] = c[v]        // điểm thưởng khi bước tới v
M[u][v] = -∞          // nếu không có cung u → v

1.2. Phép nhân (max, +)

(X ⊗ Y)[i][j] = maxk ( X[i][k] + Y[k][j] )

Phép này kết hợp (associative), nên có thể tính MT bằng luỹ thừa nhanh: O(N³ log T).

1.3. Vì sao Mk[u][v] = điểm lớn nhất đi u→v qua đúng k cạnh?

Chứng minh bằng quy nạp:

  • k = 1: đúng theo định nghĩa M.
  • Giả sử đúng với k: đường đi u → v qua k+1 cạnh = (đường u → w qua k cạnh) + (cung w → v). Theo giả thiết quy nạp, giá trị tốt nhất là max_w (Mk[u][w] + M[w][v]). Đây chính là Mk+1[u][v]. ∎

1.4. Đáp án theo công thức vector

ans = (V · MT)[1]
với V[1] = 0, V[u] = -∞ ∀ u ≠ 1
Điểm mấu chốt về c[1]: Trong công thức M[u][v] = c[v], phần thưởng tại đỉnh xuất phát (t=0) không bao giờ được cộng vào (vì M chỉ cộng c[v] khi tới v). Vậy phải cộng thêm c[1] một lần nữa ở cuối.

2. Cài đặt C++ (theo code của bạn)

2.1. Khai báo & hằng số

#include<bits/stdc++.h>
#define ll long long
using namespace std;
const int N = 252;
const ll INF = 1e18;

int n, m;
ll t, c[N], a[N][N], b[N][N], d[N][N];
BiếnVai trò
n, m, tSố đỉnh, số cung, thời gian T
c[i]Trọng số phần thưởng đỉnh i
a[u][v]Ma trận chuyển (chính là M trong lý thuyết)
b[i][j]Ma trận tích luỹ (ban đầu = ma trận đơn vị (max, +))
d[i][j]Ma trận tạm, tránh ghi đè khi nhân
⚠️ INF = 1e18 chứ không phải LLONG_MIN: vì -INF + c[v] sẽ không tràn số. Nếu dùng LLONG_MIN, phép cộng sẽ overflow ra giá trị rác.

2.2. Hàm mul — nhân ma trận (max, +)

void mul(ll x[N][N], ll y[N][N], ll z[N][N]){
    for(int i = 1; i <= n; i++){
        for(int j = 1; j <= n; j++){
            z[i][j] = -INF;
            for(int k = 1; k <= n; k++){
                if(x[i][k] != -INF && y[k][j] != -INF){
                    z[i][j] = max(z[i][j], x[i][k] + y[k][j]);
                }
            }
        }
    }
}

Giải thích từng bước:

  1. z[i][j] = -INF: mặc định "chưa có đường đi từ i tới j".
  2. Duyệt mọi đỉnh trung gian k, thử ghép i → k và k → j.
  3. Điều kiện != -INF: chỉ cộng khi cả hai vế đều có đường đi (tránh -INF + số).
  4. max(...) giữ đường đi có tổng điểm cao nhất.
So sánh 2 loại nhân ma trận:
Nhân thườngNhân (max, +)
Công thứcΣ x[i][k] · y[k][j]max_k (x[i][k] + y[k][j])
Phép "+" (cộng)cộng số nguyênmax
Phép "·" (nhân)nhân số nguyêncộng số nguyên
Phần tử 0 (identity của +)0-∞
Phần tử 1 (identity của ·)10

3. Các hàm chính

3.1. Hàm init() — đọc input, dựng ma trận

void init(){
    ios_base::sync_with_stdio(false);
    cin.tie(0); cout.tie(0);
    cin >> n >> m >> t;
    for(int i = 1; i <= n; i++) cin >> c[i];
    for(int i = 1; i <= n; i++){
        for(int j = 1; j <= n; j++) a[i][j] = -INF;
    }
    for(int i = 1; i <= m; i++){
        int u, v; cin >> u >> v;
        a[u][v] = max(a[u][v], c[v]);
    }
}
ĐoạnVai trò
ios_base::sync_with_stdio(false)Tắt đồng bộ C/C++ → đọc nhanh hơn nhiều.
cin.tie(0); cout.tie(0);Ngắt liên kết cin/cout → tăng tốc IO.
cin >> n >> m >> t;Đọc số đỉnh, số cung, thời gian.
Vòng lặp đọc c[i]Đọc trọng số phần thưởng từng đỉnh.
Khởi tạo a[i][j] = -INFMặc định "không có cung" giữa mọi cặp đỉnh.
a[u][v] = max(a[u][v], c[v])Quan trọng: vì đề cho phép nhiều cung giữa cùng cặp (u,v), dùng max để giữ cung tốt nhất.
⚠️ Điểm cần chú ý: Đề nói "Đồ thị có thể chứa nhiều cung cùng hướng giữa cùng một cặp đỉnh". Nếu chỉ gán a[u][v] = c[v], cung sau ghi đè cung trước. Phải dùng max(a[u][v], c[v]) — nhưng vì c[v] giống nhau, thực ra max ở đây chỉ mang tính an toàn, không ảnh hưởng kết quả.

3.2. Hàm solve() — luỹ thừa nhanh

void solve(){
    for(int i = 1; i <= n; i++){
        for(int j = 1; j <= n; j++){
            b[i][j] = (i == j ? 0 : -INF);
        }
    }
    while(t > 0){
        if(t & 1){
            mul(b, a, d);
            for(int i = 1; i <= n; i++){
                for(int j = 1; j <= n; j++) b[i][j] = d[i][j];
            }
        }
        mul(a, a, d);
        for(int i = 1; i <= n; i++){
            for(int j = 1; j <= n; j++) a[i][j] = d[i][j];
        }
        t >>= 1;
    }
    if(b[1][1] == -INF) cout << -1;
    else cout << b[1][1] + c[1];
}

Phân tích từng phần:

① Khởi tạo ma trận đơn vị b

b[i][j] = (i == j ? 0 : -INF);

Trong nửa vành (max, +), ma trận đơn vị có b[i][i] = 0 (đường đi dài 0 bước từ i về i) và b[i][j] = -∞ với i ≠ j.

② Luỹ thừa nhanh a^t

Thuật toán giống luỹ thừa nhị phân thông thường, chỉ khác phép nhân là mul (max, +):

while(t > 0){
    if(t & 1) b = b ⊗ a;   // nếu bit cuối = 1, nhân b với a
    a = a ⊗ a;              // bình phương a
    t >>= 1;               // dịch phải 1 bit
}

Ví dụ minh hoạ với t = 6 (nhị phân 110):

Bướct (nhị phân)t & 1Hành động
11100Không nhân; a = a²; t = 011
20111b = b · a²; a = a⁴; t = 001
30011b = b · a² · a⁴ = a⁶; t = 0

→ Kết quả: b = a⁶. Đúng như mong đợi.

③ Tại sao dùng ma trận tạm d?

Vì mul ghi đè lên ma trận thứ 3. Nếu gọi trực tiếp mul(b, a, b) thì b vừa là input vừa là output → sai. Vậy phải dùng d làm trung gian rồi copy lại.

④ Đọc đáp án

if(b[1][1] == -INF) cout << -1;
else cout << b[1][1] + c[1];
  • b[1][1] == -INF: không có hành trình từ 1 về 1 sau đúng T bước → in -1.
  • Ngược lại: b[1][1] chính là tổng phần thưởng tích luỹ dọc đường, nhưng chưa tính c[1] lúc xuất phát (t=0). Cộng thêm c[1].
Kiểm chứng với Ví dụ 1: N=3, M=4, T=6, c = [5, 2, 8], cung 1→2, 2→1, 2→3, 3→1.
Chu trình 1→2→3→1 dài 3 bước, điểm mỗi vòng = 2 + 8 + 5 = 15.
T = 6 = 2 vòng → b[1][1] = 30. Cộng c[1] = 5 → 35. ✓

3.3. Hàm main()

int main(){
    init();
    solve();
}

4. Liên hệ với cách giải thích của thầy

Cách của thầyCách code bạn
V · MT với V[1] = 0, V[u] = -∞Chỉ lấy b[1][1] + c[1]
Tính được đáp án tới mọi đỉnhChỉ tính đáp án về đỉnh 1
Tổng quát hơn, dễ mở rộngNgắn gọn hơn, ít bộ nhớ hơn

Cả hai tương đương toán học:

  • V[1] = 0 nghĩa là tại t=0, chỉ đỉnh 1 có giá trị 0 (mọi đỉnh khác không thể tới).
  • Nhân V · MT lấy phần tử [1] → chính là MT[1][1].
  • Sau đó cộng c[1] (vì M không cộng phần thưởng xuất phát).

6. Tóm tắt

BướcNội dungPhức tạp
1Dựng ma trận a[u][v] = c[v] nếu có cungO(M)
2Khởi tạo ma trận đơn vị bO(N²)
3Luỹ thừa nhanh aT bằng nhân (max, +)O(N³ log T)
4Đáp án: b[1][1] + c[1] hoặc -1O(1)
Tổng kết: Bài toán = "đường đi có trọng số lớn nhất dài đúng T bước, quay về đỉnh 1". Công cụ: ma trận trên nửa vành (max, +) + luỹ thừa nhanh. Đây là dạng kinh điển của "max-plus algebra" — xuất hiện nhiều trong bài toán đường đi dài nhất với số bước cố định.
